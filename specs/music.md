# Music Library and Player

## Status

Implemented. A compact player in the lower-right corner provides music explicitly added to `site/music/index.json`. The initial library contains the 12 chapters of the Hallowmere: Beyond the Gate soundtrack as separate stereo 48 kHz Ogg Opus files encoded at 192 kbps VBR. The original soundtrack video in the feed remains available.

## Source Sync

This spec owns `site/music.js`, `site/media-state.js`, `site/music/`, the music-player markup and styles in `site/index.html` and `site/styles.css`, the catalog checks in `scripts/check_public_bundle.py`, `scripts/update_video_audio.py`, `tests/test_music_catalog.py`, `tests/test_video_audio.py`, and `tests/media_state_test.js`.

## Behavior

- The music library is explicitly curated. Feed tags, video audio, and files merely present on disk never add tracks. A new upload becomes playable by adding its Opus file and catalog entry, validating the public bundle, and deploying Pages.
- The schema-v1 catalog has exactly `schemaVersion` and `tracks`. Each track declares unique `id` and `path`, non-empty `title`, `project` and `album`, positive finite `duration` in seconds, `contentType` equal to `audio/ogg; codecs=opus`, and `sourcePost` identifying an existing public post. Optional `artwork` is a safe `album-slug/artwork-slug.webp` path relative to the catalog, with an existing WebP signature and a 128 KiB size limit. Tracks may share a cover. Omission or an image loading failure uses the site's brand icon. The initial 192-square cover is derived from the soundtrack's published still image. The catalog accepts at most 500 tracks. Text fields are limited to 240 characters.
- Track paths use `album-slug/track-slug.opus`, relative to the catalog. The verifier rejects duplicate identities or paths, traversal, remote URLs, missing source posts, missing media, invalid Ogg Opus signatures and unlisted files. The existing public file and aggregate size limits apply.
- The catalog is fetched from the deployed site independently of the runtime post feed. A catalog failure leaves the feed usable and displays an unavailable music state. A valid empty catalog hides the player.
- Initial page load fetches no audio and never starts playback. The single audio element uses `preload="none"`, with its source assigned only on a play action. Browser storage retains the selected track, volume and position, never an autoplay preference or audio data. Progress is checkpointed through native time updates at most once every five seconds while playing, and immediately on pause, seek, hidden-page and page-exit events. A restored selection displays its saved elapsed time without requesting audio; metadata loading applies the seek only after an explicit Play action. Older preferences start at zero. Invalid, negative, completed or out-of-range offsets reset to zero, and an unknown saved track cannot transfer its offset to a different track. Explicit track changes start at zero; Previous can reset a restored position before loading audio. Storage denial leaves playback available.
- The compact charcoal bar provides cover art, the current title and project, grouped previous/play/next controls, and a visible seek line with elapsed and total times. Cover/title opens the matching dark library panel above it, with volume and the scrollable track list. The full album name remains in the playlist and title tooltip. Controls retain 44px button targets and explicit focus/hover/pressed states. A small cover loads independently of audio; changing tracks on the same album does not reload it. Track selection starts that track; next/previous preserve a paused state. Previous restarts the current track when more than three seconds have played. Ended tracks advance automatically, wrapping at the end of the library.
- Music pauses when another foreground audio element or video containing an audio stream starts or resumes, including feed videos added by filtering. Videos explicitly marked `hasAudio: false` remain independent in both directions, even before loading metadata. Muting a video that contains audio does not change its stream classification. Optional post metadata is preferred over browser track inspection because [audioTracks support varies](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/audioTracks). Legacy videos use native track lists after metadata loads when available; unknown streams retain the audio handoff. All current videos have flags measured from their actual stream headers, without re-encoding media. After adding or replacing videos, run `python3 scripts/update_video_audio.py --write` and review the metadata-only post changes. `--check` verifies flags with ffprobe in the authoring environment; public CI stays Python standard library only. Capturing `play` and `playing` listeners ignore already-paused/ended/failed media and the silent decorative showcase. Explicit music play pauses other foreground media synchronously, so the latest user action wins even when native events are still queued. A delayed music play event yields to a video that has since started. Video pause/end never resumes music automatically; resume is explicit. Playback and network failures are visible, and another track can be chosen without reloading the feed. Quick track changes ignore obsolete play-promise rejections. Loading messages clear on pause or when the track becomes ready; genuine playback errors remain visible.
- The transport shows Pause while playback is active or buffering, so a pending play request remains cancellable. Paused, ended and failed playback show Play; a failed track can be retried directly. The visible SVG icon, tooltip, accessible action label and playing class agree with the media state. Icon visibility uses the SVG's `hidden` attribute and the existing hidden-element CSS rule.
- Controls support keyboard activation, visible focus, range-input seeking and volume, and Escape to collapse the panel and return focus to its trigger. The panel and bar respect narrow viewports and safe-area insets. Supported Media Session actions expose play, pause, track navigation and seeking to system controls.
- Overflowing titles drift within the title area only while playing. Hover or keyboard focus holds the title still; reduced-motion mode keeps a static ellipsis. A ResizeObserver checks text fitting on layout/track changes. The player uses media events rather than a timer or JavaScript animation loop. Progress updates set the seek fill, and Media Session metadata includes the current artwork. Collapsing it keeps intentional playback running. No framework, external runtime library, or audio cache is introduced.

Retest the feed's search, gallery lightbox and saved-copy fallback.
- Test actual feed-video controls and videos recreated by filters. Start music and video in the same JavaScript turn in both orders, then assert only the last requested source containing audio continues. Repeat with a video explicitly lacking an audio stream and assert both it and music continue. A resumed video containing audio, or one active at a queued track-end event, must keep music paused. Stopping or ending video must not restart music; decorative background playback must not pause it.
- Verify pause/reload/resume and page-exit persistence without autoplay or initial audio requests. Cover seeks, storage denial, invalid/missing saved fields, renamed/removed tracks, track changes, completion, restored-position Previous, and rapid source changes.
